# Gemini API setup and data approval

Perform these steps **in the customer's authorized Google environment**, not in GitHub or a developer's account. Never upload real documents to local tests or GitHub artifacts.

1. Use [Google AI Studio](https://aistudio.google.com/) / the customer's Cloud project to establish Gemini Developer API access, accept applicable terms, and create a dedicated API key. A consumer Gemini subscription does not automatically provision this project/key/quota. Consult [API key setup](https://ai.google.dev/gemini-api/docs/api-key). Confirm the model you choose supports PDF/images, `generateContent`, and structured JSON output in this API project. Set its bare model ID (including version dots where applicable) as `GEMINI_MODEL`; do not enter a URL or `models/` prefix.
2. Enable/confirm billing appropriate for business documents. Review the current [Gemini API terms](https://ai.google.dev/gemini-api/terms), [pricing](https://ai.google.dev/gemini-api/docs/pricing), region availability, retention/abuse monitoring, and organizational data-processing requirements. Unpaid services may use submitted content and responses for product improvement and human review; the terms prohibit sensitive/confidential/personal information for that service category, with specified regional differences. Paid-service treatment differs and may still include safety/abuse retention. Do not assume billing means zero retention or that Workspace settings automatically apply to Gemini Developer API. Do not opt into voluntary data sharing or prompt logging without explicit business approval.
3. Jesse or his administrator must verify the effective project's billing/service category, data-use/retention terms, permitted region and relevant data-sharing settings. Business documents must not be sent until that review is approved. Record the approval privately in the customer's operating records; set `DATA_HANDLING_APPROVED=true` only afterward. The script cannot remotely attest to billing or administrative settings. This property is an operator gate, not proof of compliance.
4. Restrict the API key to the applicable Generative Language API where supported. Apps Script runs on Google infrastructure; don't apply a desktop IP/referrer restriction and then bypass it when requests fail. Use the provider's supported restrictions for this execution environment. Keep editors minimal. Put the key only in Apps Script Script Properties (`GEMINI_API_KEY`); rotate it if exposed. Calls use `x-goog-api-key`, no key in URL, no provider body in logs, and no redirect following.
5. Check the actual model's [project rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) and current pricing in AI Studio/Cloud. Limits vary by project, model, and usage tier; no universal free quota is promised. Set suitable project quotas/budget alerts and monitor costs. Budget alerts need not be a hard spend cap. Each new nonduplicate document can make one paid extraction request per attempt; interruption before durable extraction storage can incur another request on recovery.
6. Begin with synthetic documents, `MAX_ATTACHMENTS=1`, scheduling off. Verify a successful call, a rejected/malformed response, and rate-limit behavior. 429/5xx results are deferred within the attempt budget. Authentication, model access, schema rejection, blocked/truncated output, and malformed data require review; do not weaken validation to obtain a row.

The script only requests extraction, with no tools, grounding, email or billing actions. Documents are untrusted prompt input and generated fields are probabilistic. JSON/schema validation does not establish accuracy. Human comparison to the archived original remains mandatory. These links were reviewed for this build on 2026-11-21; the installer must verify current terms/settings and project-specific access before use.
